Deploying the translation backend (quick guide)

This repository includes a small Express server in `/server` that hosts a secure `/api/translate` endpoint using the Google Gemini SDK (@google/genai). Deploying it gives you a safe place to store your API key and keep translations reliable.

Quick steps (Render.com example):

1) Create a new Web Service on Render
   - Choose "Web Service"
   - Connect your GitHub repo and select the `server/` folder
   - Build command: `npm install --production` (or leave default)
   - Start command: `node index.js`
   - Environment: set `GEMINI_API_KEY` (your Gemini/Google API key)
   - Optionally set `PORT` if needed (Render sets one automatically)

2) Update frontend to point to your backend
   - Build the frontend with Vite specifying the backend base URL:

```powershell
# Windows PowerShell (example)
$env:VITE_API_BASE='https://your-backend.onrender.com/api'
npm run build
```

   - Alternatively add `VITE_API_BASE=https://your-backend.onrender.com/api` to your CI/CD build environment (GitHub Actions) so the built site points to the correct API.

3) Deploy the frontend (GitHub Pages, Netlify, etc.)
   - Deploy the `dist/` folder generated by `npm run build`.
   - If you use GitHub Actions or other CI, set `VITE_API_BASE` in the action so the built assets call your backend.

Notes & tips
- Do NOT commit your `GEMINI_API_KEY` to the repo. Use the platform's environment variables or secrets.
- If you want serverless functions instead of a full Node service, consider Vercel/Netlify functions and move the code in `/server/index.js` to a single function file.
- For testing without a real API key, set `MOCK_TRANSLATION=1` in the server environment to return a predictable mock translation.
